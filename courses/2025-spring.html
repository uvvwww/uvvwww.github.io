資料結構與演算法（DSA）

HW0 對我首先是一堂 C 語言課。八題 Judgegirl 改編題要求用 C11 獨立繳交；我在長度一的字串、大小剛好設成 64 的陣列、字典序與整數順序上接連出錯。那些不是華麗的演算法題，卻讓我真正開始對指標、資料與邊界負責。

下半學期採翻轉教學：先看影片、做線上題與 mini homework，再把課堂留給活動、題目和討論。Earth game、Software Development Team Game 與 Kahoot 沒有把課程變簡單，卻把抽象的資料結構帶進共同解題的節奏。後來在展覽看到單調佇列找凸包、BIT 做區間查詢，也更明白視覺化能留下記憶；那是活動觀摩，不是我的作業內容。

正式作業依然很硬：手寫、程式、圖論證明、DFS 的 edge case 都要求把直覺說清楚。這門課最後留下兩件事：在 C 裡對自己的資料與邊界負責，以及在翻轉教學中主動把看過的概念拿去 trace、實作、提問與重做。

作業系統（OS）

OS 的第一個門檻不是演算法，而是環境與既有 codebase。從 WSL、規格到測試，我不能把作業當成從零開始的小程式；必須先理解介面、呼叫順序、資料結構與錯誤在哪個狀態被製造出來。

MP2 的 slab allocator 讓這件事很具體：freelist 怎麼串、metadata 放哪裡、partial slab 如何維護，任何一處不一致都會變成 usertrap、timeout 或 address mismatch。真正的進展不是某個技巧，而是把 allocator 拆成可檢查的狀態與不變量。

MP3 的 EDF/CBS 排程則讓我把 deadline、budget、throttle、replenishment 從幾個名詞，變成能推演的狀態轉換。到 MP4 與期末複習，我開始能把「程式跑不動」改寫成明確問題：哪個 queue 沒更新、哪個假設不成立、哪個不變量被破壞。這是 OS 最實際的收穫。

機器學習（ML）

這門課讓我從「AI 是熱門名詞」走到「模型是一連串可驗證的實驗」。作業真正遇到的是 Colab GPU 額度、learning rate 改了之後 loss 為什麼不穩、sample code 跑得動但 inference 過不了。模型不是按下執行鍵就有答案；資料、隨機性、訓練流程和評測方式，都會改變結果。

我的問題也在這裡：作業密集時，我常先求跑完，卻沒有留足夠時間把原理吃透。這門課沒有讓我自稱「會 ML」，反而留下更清楚的標準：不能只會調參數與使用工具，還要知道 loss 在說什麼、評測在量什麼、自己的改動為什麼合理。
